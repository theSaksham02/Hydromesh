HydroMesh · Pilot specification · 2 pages · SDG 11 Target 11.5

Street-level flood intelligence using existing mobile hardware

For city engineers, disaster coordinators, and municipal CIOs evaluating an 8-week evidence pilot. This is a specification, not a sales deck.

1. Problem the pilot addresses

Municipalities lack street-level drainage visibility in the 2–6 hour window that decides routing and dispatch. Traditional IoT flood sensors cost $15,000–$50,000 per kilometre and depend on cellular backhaul. HydroMesh uses phones already in circulation, PostGIS clustering, Open-Meteo rainfall, OSRM hazard-aware walking routes, and WebSocket SOS.

2. What is already built (prototype)

  • F-07 Live risk map — PostGIS ST_DWithin / ST_MakePoint, Socket.io
  • F-11 Predictive safe routes — OSRM filtered by active hazard geometry
  • F-15 Emergency SOS — one-tap location broadcast to nearby responders
  • F-17 Accessible reporting — icon and voice, GPS water-level capture
  • F-25 Weather intelligence — Open-Meteo
  • Stack: Flutter client, Node.js/Express, PostgreSQL/PostGIS, GitHub Actions CI, MIT License

Not built: municipal cooperation dashboard (in development). Not built (research): LSTM forecasting, news-signal analysis, RL resource allocation.

3. Pilot shape (8 weeks)

WindowWork
W1–2Map layers, data feeds, operator training, reporting protocol
W3–6Live community reporting + responder accept/resolve
W7–8Joint review: warning latency, route use, dispatch time — as measured in-pilot

Engineering targets (not claimed live traffic): 1,000+ concurrent field reports per city; new-city onboard under 48 hours.
